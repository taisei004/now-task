# Notion連携

Notionで案件とタスクの全体を管理し、Nowでは次の一つに10分着手します。AIとの会話からNotionへ登録したタスクもNowに取り込みます。

## 採用理由

- Notion公式APIをWorkerのfetchから呼び出します。利用するエンドポイントが少ないため、追加SDKなしでバージョンを固定し、リクエスト間隔とエラー表示を管理します。
- Cloudflare Cronを使い、画面を閉じていても同期できるようにしました。初回設定にWebhookの受信・署名キーの登録を増やさず、2分間隔で取り込みます。
- 接続情報と同期の対応表は既存のD1を利用。秘密はAES-GCMで暗号化し、鍵をWorker Secretへ分離します。
- 要約は既存のWorkers AIと利用上限を共有し、別のAIサービスの契約やキーを増やしません。

## 接続

1. Notionに専用ページを作り、その下に案件・タスクのデータベースを用意します。
2. Notionの内部接続を作成し、コンテンツの読み取り・追加・更新を許可。専用ページに接続のアクセスを付与します。チャットでNotionを接続した認証情報は、NowのWorkerには自動的に渡りません。
3. `node scripts/init-notion-key.mjs` を一度実行。公式Wranglerでシークレット名だけ確認し、`NOTION_ENCRYPTION_KEY` が未登録の場合のみ新規作成します。既存キーを上書きしません。キーを変更すると保存済み接続を復号できなくなるため、通常は変更しないでください。
4. `pnpm db:remote` とビルド・デプロイを行います。
5. Nowの「設定 → Notion」で接続情報と内部接続のAPI Tokenを入力します。接続情報は次の形式です。

```json
{
  "rootPageId": "専用ページのUUID",
  "taskSourceId": "タスクのデータソースUUID",
  "projectSourceId": "案件のデータソースUUID"
}
```

`/#notion=` にURLエンコードしたこのJSONを付けたリンクから開くと、設定画面に接続情報をあらかじめ入力できます。TokenはこのURLに入れません。データソースIDはデータベースの表示用ページIDとは別です。

接続時に各データソースの項目と親ページを確認します。TokenはGoogleユーザーIDを追加認証データにしたAES-GCMで暗号化してD1へ保存します。暗号化キーはWorker Secretだけに置き、接続状態APIはTokenや暗号文を返しません。

## データベースの項目

案件：案件名（title）、目的・完了条件、期日、重要度、状況、分野など。同期で案件名を取得し、関連タスクに表示します。案件自体の内容はNowから更新しません。

タスクの必要項目：

| プロパティ | Notionの型 | 扱い |
| --- | --- | --- |
| タスク名 | title | Nowの本文 |
| 状況 | status | 未完了・着手中→todo、保留→held、完了→done |
| 案件 | relation | 案件データソースへの関連。Notionで管理 |
| 期日 | date | Nowには開始日を日付として反映 |
| 重要度 | select | 重要・通常 |
| タグ | multi_select | 最大5つ。新規タグの色をスキーマに追加し、既存タグの色はNotionの設定を使用 |
| 入力元 | select | Now・音声・AI会話・Discord・Notion |
| 要確認 | checkbox | trueのタスクはNowの推薦から除外 |
| 元のメモ | rich_text | 初回の書き出しで本文を保存し、その後はNotion側の内容を保持 |
| 保留理由 | rich_text | 双方向同期 |
| 着手時間（分） | number | 初期値10。整数1〜1440 |
| Now ID | rich_text | 同期の固定UUID。通常は編集不要 |

Notionの「着手中」をNowがtodoとして読み取っても、本文だけの編集で「未完了」へ戻すことはありません。変更された項目だけを書き戻します。期日の時刻や期間はNowでは編集できませんが、別項目の変更時にはNotion側の時刻・期間を保持します。

## 同期と要約

- WorkerのCronで2分ごとに同期。設定画面から手動同期も開始できます。画面を閉じてもCronは動作します。
- 一回の手動同期は変更対象6件、定期同期は10件を上限に続きの処理へ回します。変更のないタスクは処理枠を使わずに比較するため、大量の初回取り込みも次回以降に進みます。
- 接続ごとのリースで同時実行を避けます。新規作成の前にNow IDで検索し、再試行時の複製を避けます。
- 前回の同期内容、Nowの現在値、Notionの現在値の3方向を比較。異なる項目は結合し、同じ項目の衝突は停止します。設定画面でNowまたはNotionの内容を選びます。
- 同期処理中にNowが編集された場合、DBの比較付き更新で新しい編集を上書きしません。
- 削除は伝播しません。Notionで削除した項目をNowから自動削除したり、接続解除でタスクを消したりしません。
- Notionはページネーションで最大5,000件まで取得。全体を取得できない場合は書き出しを始めません。
- Notionには毎秒3リクエストを超えない間隔でアクセスします。429を含む接続失敗を表示し、次の実行で再試行します。
- 接続時に専用の「現在の優先事項（Now自動更新）」子ページを作成します。アプリが作った段落だけを更新し、親ページや利用者の自由記述は変更しません。
- タスクの内容または日付が変わったときに、上位の優先事項・理由・最初の10分をWorkers AIで要約。最大20件、本文は250文字ずつに制限し、存在するタスクIDだけを採用します。先頭は期限・重要度ルールで選んだ最優先タスクに固定します。
- AI利用は既存のユーザー別UTC日次100回枠を共有。失敗や上限時は期限・重要度に基づく要約と明示します。同じ内容での再生成を避けます。

NotionのWebhooksはこの版では使用していません。外部の双方向編集に対してNotion APIが原子的な比較付き書き込みを提供するわけではないため、更新直前のNotionの編集時刻も確認します。

## 音声とAI会話からの登録

Nowのマイクは既存のブラウザ音声認識を使い、送信前に確認できるメモとして入力します。音声経由で登録したタスクの入力元は「音声」です。

Notionへの書き込みに対応したAIには、対象のタスクデータベースを指定して「タスクに追加して」と伝えます。確定していない期日や案件は空欄、確認が必要なら「要確認」をtrueにします。新規登録のNow IDは空欄で構いません。同期がIDを割り当てます。会話の原文を残す場合は「元のメモ」に入力します。会話内容を常時監視して登録する機能はありません。

## 検証の範囲

Notion同期の自動テストは実SQLiteと実Web Cryptoを使用し、Notion HTTP APIとAIの応答はスタブです。実Notionへの継続同期・AI会話からの受信・Nowからの完了反映は、利用者が接続を完了してから確認します。
